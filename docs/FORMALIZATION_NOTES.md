- **FORMAL-EXTRACTION — resolved before F0.1**: The milestone-number inconsistency in the original F0 Draft 0 was corrected in §20.2, §20.3, and the §24 traceability table; §28 now includes F0.6. LifetimeDomain transfer/finalization is F0.6, and F0.2 remains store. No semantic rule changed. F0.0 had recorded this as a scope/roadmap discrepancy; this entry retains that history and records its resolution.
- **FORMAL-ENCODING — retained from F0.0**: `RootLocationId → Occupancy` can encode two locations with the same PlaceId and different current facts. `PlacesUnique` excludes that malformed state and implements WF-4. Location-based carriers also expose duplicate package installation. F0.1's old-fact invalidation proof uses place uniqueness to rule out another root keeping the target's old current fact live.
- **FORMAL-ENCODING — retained from F0.0**: PlaceId and RootLocationId remain nominally distinct instead of using the optional identification in F0 §4.2. Predicates establish their correspondence for well-formed live roots and the uniqueness of a live incarnation identity.
- **FORMAL-ENCODING — F0.1 history**: `usedValueFacts : Finset ValueFactId` is proof-only ghost state. `ValueFactsRecorded` covers all current facts; `FreshValueFact` excludes every recorded allocation. Raw replace inserts the new fact without deleting retired facts. `replace_history_monotone` proves retention, and a countermodel proves a currently dead identity can still be historically used. Initial states must seed the full prior history; future allocating operations must extend it. This does not require runtime/compiler history storage. At F0.1 a nominally typed usedIncarnations set was deferred to F0.4; it is now implemented as described below.
- **FORMAL-LEMMA — F0.1 non-laundering**: The preservation theorem projects the legal step's post-state condition. The substantive negative proof combines explicit raw candidate updates, old-fact invalidation, unchanged dependency data, and old-package survival. The incoming-package case uses the same invalidation lemma. No theorem assumes every raw candidate is well formed. An independent legal example excludes vacuous legality; the unchecked dependency countermodel satisfies all other invariant fields.
- **FORMAL-ENCODING — F0.2 atomic consumption**: Store removes the old carrier and retains its package-table record. Uncarried data is not a survivor; no runtime physical deletion or destructor semantics are implied. The candidate is built directly, without requiring a legal replace. Old discardability uses the existing Boolean proof-side static abstraction, not a runtime check; incoming discardability is not a premise. Historical freshness reuses F0.1 unchanged.
- **FORMAL-LEMMA — F0.2 survivor distinction**: Carrier uniqueness excludes incoming = old and any second old installation. Only the old package ceases to survive; every other survivor stays tracked. Old-fact invalidation then rejects dependencies in a third survivor or incoming package. The same concrete pre-state rejects replace but admits store with an old self-dependency. Separate break-tests show dependency validation and the discardability guard are independently necessary; WellFormed does not authorize discarding a non-discardable value.
- **FORMAL-ENCODING — F0.3 cases/freshness**: A swap-specific sum separates same-place (no new-fact arguments, exact state identity) and distinct-place (one atomic carrier exchange). `FreshValueFactPair` requires two unused and mutually distinct IDs; this is a proof encoding of two fresh ghost allocations, not a normative global runtime stamp format. Both are inserted without shrinking history. Distinct locations correspond to distinct places by WellFormed; package inequality is derived from carrier uniqueness. Package/dependency tables and place-owned governing domains do not exchange or retarget.
- **FORMAL-LEMMA — F0.3 non-laundering**: Both old facts become dead, both packages survive, and every other survivor stays tracked. Ordinary post-state DependenciesValid rejects self/cross/cyclic and third-survivor old-fact dependencies. A concrete self-dependent pre-state permits same-place but rejects distinct swap. The cyclic raw countermodel satisfies every other invariant; the independent legal witness uses non-discardable packages and different governing domains. No Copy or discardability requirement is introduced.
- **FORMAL-ENCODING — F0.4 history extension**: State gains proof-only usedIncarnations and WellFormed gains IncarnationsRecorded. Empty/old candidates/fixtures are updated without altering existing theorem statements or weakening claims. Replace/store/same/distinct swap preserve the set exactly. LiveIncarnation and Governs are derived views. Allocate only during initialize; ended incarnation/current-fact IDs remain recorded through take/destroy.
- **FORMAL-ENCODING — F0.4 typed sites**: Vacant abstracts empty occupancy responsibility, not a full source-level slot value. RootSiteLayout fixes an injective location-to-place association in the execution proof context. Initialize consults that association; reinitialization keeps the place and freshens incarnation/current fact. Nominal ID types remain distinct; no fresh PlaceId allocation or extra global layout invariant is added. F0 §4.2 permits such correspondence; Draft 17.4 §14.1–2 conserves the typed occupancy site. The fixture's index-preserving layout is an encoding, not normative ID equality or backing geometry.
- **FORMAL-LEMMA — F0.4 lifecycle/survivors**: Initialize/take conserve vacancy and a unique package carrier. Same-site reinitialize uses new identities while both old identities stay recorded. Take returns the old survivor and rejects self/third old-current dependencies; destroy consumes old-only dependency but still rejects third survivors. Both end root governing relation while preserving DomainLive. Domain equality and caller authorization are independently checked; discardability is applicability, not WellFormed.
- **FORMAL-ENCODING — F0.5 reference subset**: PtrToken is a persistent external location/incarnation value, not a current-fact or domain token. During F0.5, State and WellFormed were unchanged; F0.6 extends them below. Arbitrary Lean construction/equality is not source-safe minting/pointer equality; initialize's result is linked by a theorem. Current governing state is read only after exact incarnation correspondence. RawAcquireRef separates evidenceDomain, possession of ordinary stability evidence (Prop), and omitted access/provenance/representation/backing obligations (Prop). DomainLive alone supplies no caller evidence. No persistent acquired-ref value is introduced.
- **FORMAL-LEMMA — F0.5 stale safety**: Acquisition yields exact location/incarnation and matching governing domain, hence live incarnation/domain. F0.4 end/history lemmas reject old tokens after take/destroy and after fresh same-site reinitialize. Both complete concrete traces use one fixed RootSiteLayout and location: old token rejects, new token accepts. Replace changes current fact without staling the token. A private freshness-only broken initialize satisfies all other raw conditions and all pre/post invariants, yet revives the old token; private acquisition omissions isolate incarnation/domain match necessity.
- **FORMAL-SCOPE — F0.5 acquisition boundary**: AcquireRef proves point-of-acquisition legality/current liveness. It does not yet prove full future-use scope stability. Read/write share this kernel; no Copy, exclusivity, or ending authority is added. Lexical scope identity/dependency/non-escape, ref -> ptr, backing/provenance geometry remain deferred; domain transfer/finalization are now covered by the F0.6 subset below. Omitted static/access assumptions are caller obligations, not NewLang semantic assumptions introduced by custom logic.
- **FORMAL-SCOPE — remaining F0 boundary**: Replace, store, swap, initialize, take, destroy, acquisition and the F0.6 domain lifecycle subset are implemented. Borrow-checker/type-compatibility derivations remain caller-supplied proposition premises; production does not make them universally True and replace/store/swap require no exclusive/lifetime-ending authority. Full source-level ptr/ref/slot carriers, lexical use scopes, finite-support proofs, payload/authority algebra, structural subobjects, scope/backing geometry and actual LifetimeDomain-typed object geometry remain out of scope. Root-only restrictions are structurally satisfied by flat F0 occupancy. Initialize uses ordinary authorization; take/destroy require an abstract ending-authority proof tied to the same governing DomainId.

## F0.6 findings

- **FORMAL-ENCODING — abstract domain ownership:** A separate nominal DomainValueCarrierId and `DomainId → Option DomainValueCarrierId` map distinguish live identity from current value carrier. DomainCarrierCoherent requires live iff carrier exists. There is no reverse injectivity: distinct domain identities may share one carrier. This is abstract ownership, not source/runtime layout, address, root place, package data or incarnation. Actual LifetimeDomain-typed source/destination objects remain unmodeled. Finalization clears D's entry, not a global carrier shared by other identities.
- **FORMAL-ENCODING — mechanical regression:** State.empty has no domain carriers. Earlier candidates preserve the carrier map exactly; fixtures seed every live domain and supply the ninth WellFormed field. The old public theorem statements and all 208 audits are retained. Nine new coherence/frame audits accompany 37 domain production proofs and 12 concrete controls: 266 total.
- **FORMAL-LEMMA — transfer identity:** Raw transfer preserves the entire live-domain set, occupancy, governing relations, package/dependency data, loose carriers, both histories, LiveFacts and survivors. It changes only D's current carrier. Raw transfer from WellFormed pre proves WellFormed post. Governed roots and DomainLive dependencies therefore do not block transfer. Acquisition observation is preserved for the same ptr/domain given separate post caller stability/access proofs; no future-use ref stability claim follows.
- **FORMAL-LEMMA — no stranding on finalization:** Raw end removes D and clears its carrier entry without touching roots or packages. Legal post DomainsValid derives no governed live root; legal post DependenciesValid derives no surviving DomainLive(D) dependency. These conditions are not duplicated as raw guards. Concrete same-state contrasts, legal independent finalization, and destroy-then-finalize supply positive and negative evidence. Dead/repeated end, wrong carrier and missing caller premise reject.
- **FORMAL-LEMMA — isolated break-tests:** A private identity-renaming transfer has WellFormed endpoints but violates same-identity transfer. Two raw finalization candidates satisfy eight of nine WellFormed fields: one fails only DomainsValid, the other only DependenciesValid. Thus operation identity is a raw semantic rule, while modeled finalization conflicts are ordinary post-invariant consequences.
- **FORMAL-SCOPE — caller boundaries:** TransferAllowed abstracts actual source-current-value capability conflicts and applicability; DomainLive dependencies are distinct from dependencies on a source object's current value. CanFinalize abstracts omitted lexical/scoped capabilities. Neither premise is universally True in production; fixtures choose True only to isolate modeled obligations. No source ref scoping or general authority algebra is claimed. LifetimeDomain non-Discardable is represented by explicit end, independently of the package Bool abstraction.
- **FORMAL-SCOPE — creation and closure:** No domain creation or resurrection transition is added. Draft 17.4 §13.1's fresh creation identity requirement remains an obligation for future creation/recreation; usedDomainIds is unnecessary for the present transitions, which either retain or shrink the domain set. F1, BackingRegion, structural subobjects and lexical ref scope remain outside scope. F0 closure is a review of this limited flat kernel, not whole-language or compiler safety.

No new FORMAL-HOLE, FORMAL-AMBIGUITY or FORMAL-EXTRACTION was identified in inspected Draft 17.4 §13.1–3 / §14.5–6. Identity/carrier separation and explicit no-stranding finalization agree with those rules. Normative Draft 17.4 is unchanged; the resolved milestone extraction history above is retained. See [F0.6 report](F0_6_DOMAIN_TRANSFER_FINALIZATION_REPORT.md) for theorem inventory, M8 feedback and closure assessment. ## F1.0 structural refinement

- **FORMAL-ENCODING — finite semantic paths:** Reuse PlaceId; each finite root layout maps tracked nodes to root-relative List Nat paths. Empty-path root, injectivity and immediate-prefix closure give a tree. Strict length excludes cycles; duplicate-parent malformed layouts are rejected. Labels do not prescribe field syntax, byte offsets or ABI. Root-only domain/occupancy metadata is not copied into child fragments.
- **FORMAL-ENCODING — canonical ownership:** Each node stores one incarnation, current fact and LocalDeps. SubtreeDeps is a derived finite union, not a parent copy. A sibling subtree atom must have its own local owner, though identical atoms may be independently owned on both sides. Finite live-root support and flat loose values keep this scaffold small; no general heap graph or structural operation exists.
- **FORMAL-ENCODING — conservative erasure:** Strategy A maps exact live child facts to their enclosing root current fact; a derived coarse root summary combines the subtree image (strategy-B boundary). Domain facts preserve identity and stale/unknown value facts remain unchanged. Installed package data and root occupancy are derived, not duplicated; root discardability and all ghost histories are retained. Coarse images can lose sibling precision; this is state abstraction, not a one-to-one Step simulation claim.
- **FORMAL-LEMMA — refinement:** Thirteen F1-side fields independently imply all nine F0 fields; no erased WellFormed premise is embedded. Root fact/incarnation/domain anchors, precise fact liveness, global identity recording/uniqueness, local-to-actual-package obligation conservation and the central erasure theorem are checked. Pair and nested fixtures rule out vacuity.
- **FORMAL-LEMMA — controls:** Concrete ownership/overlap/history witnesses, cyclic graph impossibility, duplicate-parent/fact/incarnation/stale rejection and private broken erasure are checked. A recorded stale child fact remains non-live. Broken erasure can preserve F0 WellFormed while losing an obligation, showing why conservation is a separate proof requirement.
- **FORMAL-SCOPE — next stages:** F1.0 is state/invariant scaffold only. Fixed/whole-aggregate operations are F1.1, conditional occurrence F1.2, BackingRegion/placement F1.3, raw occupancy/Storage/slot F1.4, relocation F1.5. Loose aggregates, lexical refs/functions and source API remain outside this task. No OccurrenceId, backing ID, allocator framework or F0 semantic change is added.

## F1.1 fixed structural transitions

- **FORMAL-ENCODING — representation audit:** Flat loose ValuePackage cannot retain relative child ownership. A conservative CurrentState layer adds structured carried values, opaque local content tokens and fixed type-capability metadata while leaving every F0/F1.0 Lean file unchanged. Precise loose values have checked flat summaries. Relative positions are semantic coordinates, not source paths/ABI. Carried dependencies reference exact facts but place/incarnation/domain ownership never enters the value.
- **FORMAL-ENCODING — structural freshness:** Live/tracked overlap support covers target, ancestors and descendants. Finite fresh-map injectivity and historical exclusion prevent reuse/aliasing; history grows by the image and incarnation history stays. Same-place swap has no supply. Distinct swap uses one union, hence one allocation per shared ancestor. KnownDisjoint alone is never authority.
- **FORMAL-ENCODING — carrier/type boundary:** Whole-root replacement uses old/incoming root carriers; child extraction creates a distinct loose result without exchanging the enclosing root carrier. Store adds no old result and removes the input loose carrier; inactive tables are not survivors. Static Discardable comes from the target's type metadata, not the root or runtime payload. All operations preserve that metadata.
- **FORMAL-LEMMA — structural conformance:** Layout, all fixed incarnations, domains/governing relations and live support stay; affected facts die, disjoint facts stay live. Exact extraction/installation conserves local content/dependencies. Replace old-result/incoming/external conflicts reject; atomic store eliminates old-only dependency but rejects surviving/incoming conflicts. Same-place self-dependent swap accepts; distinct self/cyclic/third-survivor dependencies reject, while external disjoint dependencies accept. Non-discardable swap witnesses add no Copy/ending requirement.
- **FORMAL-LEMMA — erasure and controls:** The reviewed central F1-to-F0 WellFormed theorem remains unchanged. A new carried-obligation theorem proves membership in the actual erased package table. Leaf/nested/root and aggregate/two-root swap witnesses rule out vacuity. Private broken candidates isolate ancestor/descendant omission, incarnation refresh, sibling over-invalidation, extraction/flattening loss, guard omission, same-place allocation, overlap applicability and freshness errors.
- **FORMAL-SCOPE — refinement:** Legal preservation is a post-invariant projection; raw construction and non-laundering are separate substantive proofs. Precision-losing state erasure is not exact Step simulation. Only fixed support transitions are implemented; conditional occurrence, physical geometry, Storage/slot, relocation, lexical future-use, functions and source syntax remain deferred.
