Draft 17.4 remains the normative source of truth and is unchanged. The non-normative bridge has the editorial milestone correction below.

- **FORMAL-EXTRACTION — resolved before F0.1**: The milestone-number inconsistency in the original F0 Draft 0 was corrected in §20.2, §20.3, and the §24 traceability table; §28 now includes F0.6. LifetimeDomain transfer/finalization is F0.6, and F0.2 remains store. No semantic rule changed. F0.0 had recorded this as a scope/roadmap discrepancy; this entry retains that history and records its resolution.
- **FORMAL-ENCODING — retained from F0.0**: `RootLocationId → Occupancy` can encode two locations with the same PlaceId and different current facts. `PlacesUnique` excludes that malformed state and implements WF-4. Location-based carriers also expose duplicate package installation. F0.1's old-fact invalidation proof uses place uniqueness to rule out another root keeping the target's old current fact live.
- **FORMAL-ENCODING — retained from F0.0**: PlaceId and RootLocationId remain nominally distinct instead of using the optional identification in F0 §4.2. Predicates establish their correspondence for well-formed live roots and the uniqueness of a live incarnation identity.
- **FORMAL-ENCODING — F0.1 history**: `usedValueFacts : Finset ValueFactId` is proof-only ghost state. `ValueFactsRecorded` covers all current facts; `FreshValueFact` excludes every recorded allocation. Raw replace inserts the new fact without deleting retired facts. `replace_history_monotone` proves retention, and a countermodel proves a currently dead identity can still be historically used. Initial states must seed the full prior history; future allocating operations must extend it. This does not require runtime/compiler history storage. At F0.1 a nominally typed usedIncarnations set was deferred to F0.4; it is now implemented as described below.
- **FORMAL-LEMMA — F0.1 non-laundering**: The preservation theorem projects the legal step's post-state condition. The substantive negative proof combines explicit raw candidate updates, old-fact invalidation, unchanged dependency data, and old-package survival. The incoming-package case uses the same invalidation lemma. No theorem assumes every raw candidate is well formed. An independent legal example excludes vacuous legality; the unchecked dependency countermodel satisfies all other invariant fields.
- **FORMAL-ENCODING — F0.2 atomic consumption**: Store removes the old carrier and retains its package-table record. Uncarried data is not a survivor; no runtime physical deletion or destructor semantics are implied. The candidate is built directly, without requiring a legal replace. Old discardability uses the existing Boolean proof-side static abstraction, not a runtime check; incoming discardability is not a premise. Historical freshness reuses F0.1 unchanged.
- **FORMAL-LEMMA — F0.2 survivor distinction**: Carrier uniqueness excludes incoming = old and any second old installation. Only the old package ceases to survive; every other survivor stays tracked. Old-fact invalidation then rejects dependencies in a third survivor or incoming package. The same concrete pre-state rejects replace but admits store with an old self-dependency. Separate break-tests show dependency validation and the discardability guard are independently necessary; WellFormed does not authorize discarding a non-discardable value.
- **FORMAL-ENCODING — F0.3 cases/freshness**: A swap-specific sum separates same-place (no new-fact arguments, exact state identity) and distinct-place (one atomic carrier exchange). `FreshValueFactPair` requires two unused and mutually distinct IDs; this is a proof encoding of two fresh ghost allocations, not a normative global runtime stamp format. Both are inserted without shrinking history. Distinct locations correspond to distinct places by WellFormed; package inequality is derived from carrier uniqueness. Package/dependency tables and place-owned governing domains do not exchange or retarget.
- **FORMAL-LEMMA — F0.3 non-laundering**: Both old facts become dead, both packages survive, and every other survivor stays tracked. Ordinary post-state DependenciesValid rejects self/cross/cyclic and third-survivor old-fact dependencies. A concrete self-dependent pre-state permits same-place but rejects distinct swap. The cyclic raw countermodel satisfies every other invariant; the independent legal witness uses non-discardable packages and different governing domains. No Copy or discardability requirement is introduced.
- **FORMAL-ENCODING — F0.4 history extension**: State gains proof-only usedIncarnations and WellFormed gains IncarnationsRecorded. Empty/old candidates/fixtures are updated without altering existing theorem statements or weakening claims. Replace/store/same/distinct swap preserve the set exactly. LiveIncarnation and Governs are derived views. Allocate only during initialize; ended incarnation/current-fact IDs remain recorded through take/destroy.
- **FORMAL-ENCODING — F0.4 typed sites**: Vacant abstracts empty occupancy responsibility, not a full source-level slot value. RootSiteLayout fixes an injective location-to-place association in the execution proof context. Initialize consults that association; reinitialization keeps the place and freshens incarnation/current fact. Nominal ID types remain distinct; no fresh PlaceId allocation or extra global layout invariant is added. F0 §4.2 permits such correspondence; Draft 17.4 §14.1–2 conserves the typed occupancy site. The fixture's index-preserving layout is an encoding, not normative ID equality or backing geometry.
- **FORMAL-LEMMA — F0.4 lifecycle/survivors**: Initialize/take conserve vacancy and a unique package carrier. Same-site reinitialize uses new identities while both old identities stay recorded. Take returns the old survivor and rejects self/third old-current dependencies; destroy consumes old-only dependency but still rejects third survivors. Both end root governing relation while preserving DomainLive. Domain equality and caller authorization are independently checked; discardability is applicability, not WellFormed.
- **FORMAL-ENCODING — F0.5 reference subset**: PtrToken is a persistent external location/incarnation value, not a current-fact or domain token. State and WellFormed remain unchanged. Arbitrary Lean construction/equality is not source-safe minting/pointer equality; initialize's result is linked by a theorem. Current governing state is read only after exact incarnation correspondence. RawAcquireRef separates evidenceDomain, possession of ordinary stability evidence (Prop), and omitted access/provenance/representation/backing obligations (Prop). DomainLive alone supplies no caller evidence. No persistent acquired-ref value is introduced.
- **FORMAL-LEMMA — F0.5 stale safety**: Acquisition yields exact location/incarnation and matching governing domain, hence live incarnation/domain. F0.4 end/history lemmas reject old tokens after take/destroy and after fresh same-site reinitialize. Both complete concrete traces use one fixed RootSiteLayout and location: old token rejects, new token accepts. Replace changes current fact without staling the token. A private freshness-only broken initialize satisfies all other raw conditions and all pre/post invariants, yet revives the old token; private acquisition omissions isolate incarnation/domain match necessity.
- **FORMAL-SCOPE — F0.5 acquisition boundary**: AcquireRef proves point-of-acquisition legality/current liveness. It does not yet prove full future-use scope stability. Read/write share this kernel; no Copy, exclusivity, or ending authority is added. Lexical scope identity/dependency/non-escape, ref -> ptr, backing/provenance geometry and domain transfer/finalization remain deferred. Omitted static/access assumptions are caller obligations, not NewLang semantic assumptions introduced by custom logic.
- **FORMAL-SCOPE — remaining**: Replace, store, swap, initialize, take and destroy are implemented. Borrow-checker/type-compatibility derivations remain caller-supplied proposition premises; production does not make them universally True and replace/store/swap require no exclusive/lifetime-ending authority. Full source-level ptr/ref/slot carriers, lexical use scopes, finite-support proofs, payload/authority algebra, structural subobjects, scope/backing geometry, and domain transfer/finalization remain out of scope. Root-only restrictions are structurally satisfied by flat F0 occupancy. Initialize uses ordinary authorization; take/destroy require an abstract ending-authority proof tied to the same governing DomainId.
