- **FORMAL-LEMMA — F0.3 non-laundering**: Both old facts become dead, both packages survive, and every other survivor stays tracked. Ordinary post-state DependenciesValid rejects self/cross/cyclic and third-survivor old-fact dependencies. A concrete self-dependent pre-state permits same-place but rejects distinct swap. ## F0.6 findings

- **FORMAL-ENCODING — abstract domain ownership:** A separate nominal DomainValueCarrierId and `DomainId → Option DomainValueCarrierId` map distinguish live identity from current value carrier. DomainCarrierCoherent requires live iff carrier exists. There is no reverse injectivity: distinct domain identities may share one carrier. This is abstract ownership, not source/runtime layout, address, root place, package data or incarnation. Actual LifetimeDomain-typed source/destination objects remain unmodeled. Finalization clears D's entry, not a global carrier shared by other identities.
- **FORMAL-ENCODING — mechanical regression:** State.empty has no domain carriers. Earlier candidates preserve the carrier map exactly; fixtures seed every live domain and supply the ninth WellFormed field. The old public theorem statements and all 208 audits are retained. Nine new coherence/frame audits accompany 37 domain production proofs and 12 concrete controls: 266 total.
- **FORMAL-LEMMA — transfer identity:** Raw transfer preserves the entire live-domain set, occupancy, governing relations, package/dependency data, loose carriers, both histories, LiveFacts and survivors. It changes only D's current carrier. Raw transfer from WellFormed pre proves WellFormed post. Governed roots and DomainLive dependencies therefore do not block transfer. Acquisition observation is preserved for the same ptr/domain given separate post caller stability/access proofs; no future-use ref stability claim follows.
- **FORMAL-LEMMA — no stranding on finalization:** Raw end removes D and clears its carrier entry without touching roots or packages. Legal post DomainsValid derives no governed live root; legal post DependenciesValid derives no surviving DomainLive(D) dependency. These conditions are not duplicated as raw guards. Concrete same-state contrasts, legal independent finalization, and destroy-then-finalize supply positive and negative evidence. Dead/repeated end, wrong carrier and missing caller premise reject.
- **FORMAL-LEMMA — isolated break-tests:** A private identity-renaming transfer has WellFormed endpoints but violates same-identity transfer. Two raw finalization candidates satisfy eight of nine WellFormed fields: one fails only DomainsValid, the other only DependenciesValid. Thus operation identity is a raw semantic rule, while modeled finalization conflicts are ordinary post-invariant consequences.
- **FORMAL-SCOPE — caller boundaries:** TransferAllowed abstracts actual source-current-value capability conflicts and applicability; DomainLive dependencies are distinct from dependencies on a source object's current value. CanFinalize abstracts omitted lexical/scoped capabilities. Neither premise is universally True in production; fixtures choose True only to isolate modeled obligations. No source ref scoping or general authority algebra is claimed. LifetimeDomain non-Discardable is represented by explicit end, independently of the package Bool abstraction.
- **FORMAL-SCOPE — creation and closure:** No domain creation or resurrection transition is added. Draft 17.4 §13.1's fresh creation identity requirement remains an obligation for future creation/recreation; usedDomainIds is unnecessary for the present transitions, which either retain or shrink the domain set. F1, BackingRegion, structural subobjects and lexical ref scope remain outside scope. F0 closure is a review of this limited flat kernel, not whole-language or compiler safety.

No new FORMAL-HOLE, FORMAL-AMBIGUITY or FORMAL-EXTRACTION was identified in inspected Draft 17.4 §13.1–3 / §14.5–6. ## F1.0 structural refinement

- **FORMAL-ENCODING — finite semantic paths:** Reuse PlaceId; each finite root layout maps tracked nodes to root-relative List Nat paths. Empty-path root, injectivity and immediate-prefix closure give a tree. Strict length excludes cycles; duplicate-parent malformed layouts are rejected. Labels do not prescribe field syntax, byte offsets or ABI. Root-only domain/occupancy metadata is not copied into child fragments.
- **FORMAL-ENCODING — canonical ownership:** Each node stores one incarnation, current fact and LocalDeps. SubtreeDeps is a derived finite union, not a parent copy. A sibling subtree atom must have its own local owner, though identical atoms may be independently owned on both sides. Finite live-root support and flat loose values keep this scaffold small; no general heap graph or structural operation exists.
- **FORMAL-ENCODING — conservative erasure:** Strategy A maps exact live child facts to their enclosing root current fact; a derived coarse root summary combines the subtree image (strategy-B boundary). Domain facts preserve identity and stale/unknown value facts remain unchanged. Installed package data and root occupancy are derived, not duplicated; root discardability and all ghost histories are retained. Coarse images can lose sibling precision; this is state abstraction, not a one-to-one Step simulation claim.
- **FORMAL-LEMMA — refinement:** Thirteen F1-side fields independently imply all nine F0 fields; no erased WellFormed premise is embedded. Root fact/incarnation/domain anchors, precise fact liveness, global identity recording/uniqueness, local-to-actual-package obligation conservation and the central erasure theorem are checked. Pair and nested fixtures rule out vacuity.
- **FORMAL-LEMMA — controls:** Concrete ownership/overlap/history witnesses, cyclic graph impossibility, duplicate-parent/fact/incarnation/stale rejection and private broken erasure are checked. A recorded stale child fact remains non-live. Broken erasure can preserve F0 WellFormed while losing an obligation, showing why conservation is a separate proof requirement.
- **FORMAL-SCOPE — next stages:** F1.0 is state/invariant scaffold only. Fixed/whole-aggregate operations are F1.1, conditional occurrence F1.2, BackingRegion/placement F1.3, raw occupancy/Storage/slot F1.4, relocation F1.5. Loose aggregates, lexical refs/functions and source API remain outside this task. No OccurrenceId, backing ID, allocator framework or F0 semantic change is added.

## F1.1 fixed structural transitions

- **FORMAL-ENCODING — structural freshness:** Live/tracked overlap support covers target, ancestors and descendants. - **FORMAL-ENCODING — carrier/type boundary:** Whole-root replacement uses old/incoming root carriers; child extraction creates a distinct loose result without exchanging the enclosing root carrier. Store adds no old result and removes the input loose carrier; inactive tables are not survivors. Static Discardable comes from the target's type metadata, not the root or runtime payload. - **FORMAL-LEMMA — structural conformance:** Layout, all fixed incarnations, domains/governing relations and live support stay; affected facts die, disjoint facts stay live. Replace old-result/incoming/external conflicts reject; atomic store eliminates old-only dependency but rejects surviving/incoming conflicts. - **FORMAL-LEMMA — erasure and controls:** The reviewed central F1-to-F0 WellFormed theorem remains unchanged. A new carried-obligation theorem proves membership in the actual erased package table. - **FORMAL-SCOPE — refinement:** Legal preservation is a post-invariant projection; raw construction and non-laundering are separate substantive proofs. Only fixed support transitions are implemented; conditional occurrence, physical geometry, Storage/slot, relocation, lexical future-use, functions and source syntax remain deferred.
